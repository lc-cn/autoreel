# 定时任务指令（任何 AI 工具通用）

最省事的做法：在你的 AI 工具里打开这个仓库，说「**帮我设置自影的定时任务**」，安装向导（`autoreel-setup` 技能）会按你的工具建好。下面是手动创建时用的指令。

每个启用的频道建一个任务，时间是 `channel.json` 的 `schedule.make`（北京时间），仓库选你自己的这个仓库，指令照抄并把 `<频道id>` 换掉。流程细节都在仓库里（`AGENTS.md` → `autoreel` 技能 → 频道的 `brief.md`），以后改流程只改仓库，不用改定时任务。

```
按仓库 AGENTS.md 的说明，制作今天的 <频道id> 频道，用 tools/make.py 推送到 clip-日期-<频道id> 分支（日期按北京时间）。这是我安排的每日任务，我授权你推送这个分支（以及频道要求时把 inputs/ 里用过的素材标记为已做并提交到默认分支）。不要登录或调用任何视频平台。
```

`days_ahead` 为 1 的频道（历史上的今天、成语）把「今天的」改成「今天和明天两期」。

## 发布状态检查（可选）

在最后一个发布时间之后半小时（或一天几次）运行：

```
只读检查：读取本仓库今天（北京时间）各个 clip-日期-<频道> 分支的 status.json，频道列表见 autoreel.config.json 的 channels，只检查发布时间（channel.json 的 schedule.publish）已经过了的频道。
- 分支不存在：说明这一期没有生成，查看原因，能修就按 AGENTS.md 补做并推送。
- 分支存在但没有 status.json，或 status 不是 published：提醒我打开自影插件弹窗确认（能推送通知就推送，否则运行 python3 tools/notify.py warn "<频道> 没有发布" "<原因>"）。
- 都已发布：汇总成一句话。
不要修改默认分支，不要删除分支，不要登录任何视频平台。
```

## 没有定时任务功能的 AI 工具

用 GitHub Actions（[`schedulers/github-actions/`](../schedulers/github-actions/README.md)）或自己电脑的 cron / launchd（[`schedulers/local/`](../schedulers/local/README.md)）。

## 小贴士

- 第一次运行时，AI 工具推送前可能会请你确认授权，选「允许」或回复「同意，以后每天都可以直接推送」。
- 手动补做：在任意会话里说「按 AGENTS.md 补做今天的 kuaibao」。
