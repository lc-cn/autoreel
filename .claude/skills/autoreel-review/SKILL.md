# 自影 · 每周复盘与自动改进

全程用中文。目标：让写稿规则跟着这个账号的真实数据走，而不是凭感觉。**只用数据撑得住的结论；样本小就明说。**

仓库根目录记为 `$REPO`，开始前 `git -C $REPO pull -q`。

## 第 1 步：算数据（脚本算，不要自己估）

```bash
python3 $REPO/tools/analyze.py --write --apply
```

- 周报写进 `history/周报/<日期>.md`，汇总写进 `history/分析.json`。
- `--apply` 会按「留存分 = 5秒完播率 − 2秒跳出率」更新各频道 `channel.json` 的 `format_weights`（视频形式轮换比例）。每种形式攒够 3 期才调整，每种至少保留 15%。改动自动记进 `history/改进记录.md`。这一步是脚本按固定规则做的，不要手动改权重。
- 数据来源：浏览器插件每晚采集的 `history/数据.jsonl`。如果最近 2 天没有新采集（看 `collected` 时间），在汇报里提醒用户检查插件（Chrome 要开着、抖音要登录）。

## 第 2 步：找规律

读周报、`history/经验.md`（没有就新建）、`history/改进记录.md`，再看：

1. **2 秒跳出率最低 / 最高的 5 期**：对比它们的标题和钩子句（发布记录 `history/发布记录.jsonl` 里有 hook），找共同点：话题离观众多近、钩子是什么句式、第一句有没有信息量。
2. **频道 × 形式、钩子类型**：只采纳周报里标「可信」的差异；「待观察」的只记下来，不当结论。
3. **趋势**：各频道本周 vs 上周，变化超过 5 个百分点的，找可能的原因（换了形式？题材？时长？），说不出原因就写「原因不明」。

## 第 3 步：更新经验库 `history/经验.md`（自动改进）

写稿时 autoreel 技能会先读这个文件，所以这里写的就是下周的写稿规则。格式：

```markdown
# 自影 · 经验库（每周复盘更新，写稿前必读）

## 通用
- 【可信】钩子句用「按常理该 A、结果却是 B」，2 秒跳出明显更低。依据：11-13～11-26 跳出率最低的 5 期都是这种（28–40%），其余平均 54%。（2026-11-30）

## 一条讲透
- 【待观察】……
```

规则：
- 每条写清：结论、依据（期数、数字、日期范围）、状态（【可信】或【待观察】）、写入日期。
- 新数据和旧结论矛盾时，改掉或删掉旧结论，在 `history/改进记录.md` 记一笔。
- 只写能指导写稿的结论（选什么题、钩子怎么写、多长、用什么形式）。不写空话。
- 全文控制在 40 行以内，旧的、被更新覆盖的删掉。
- 经验库不能推翻硬规则：事实核查、来源要求、平台规则、AI 标识、不做时政立场，这些永远优先。

## 第 4 步：需要用户拍板的，写成建议，不要自己改

这些改动影响大，只在汇报里提建议并附依据，等用户同意：
- 停用、恢复或新建频道；改发布时间；改时长（`say_total`、`max_seconds`）
- 改 `brief.md` 的结构性要求；增删视频形式
- 任何花钱的改动（付费配音、付费素材）

## 第 5 步：提交

只提交 `history/`（周报、分析、经验库、改进记录）和 `channels/*/channel.json` 里脚本改的 `format_weights`：

```bash
git -C $REPO add history channels/*/channel.json
git -C $REPO commit -m "autoreel: 每周复盘 <日期>"
git -C $REPO push
```

## 第 6 步：汇报（发给用户）

5–8 行：本周各频道一句话（变好 / 变差 / 持平，附关键数字）；新写进经验库的结论；形式比例的调整；需要用户拍板的建议（每条附依据）。用 PushNotification（status 设为 proactive）推一句摘要（如果有这个工具）。
