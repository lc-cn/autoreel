# 自影 · 安装与定时任务向导

全程用中文，一次只问一组问题；能用选项卡片就用，没有就给编号选项，并标出推荐项。用户说"你定"就按推荐走。写文件、提交、推送、创建定时任务之前，先把要做的改动列给用户确认。

仓库根目录记为 `$REPO`。开始前 `git -C $REPO pull -q`。

## 第 1 步：了解环境（自己判断，必要时问一句）

1. **你是哪个 AI 工具、在哪里运行**：本地终端、云端会话，还是 IDE 里。
2. **你自己有没有创建定时任务的能力**：查看你的工具列表里有没有「定时任务 / scheduled task / routine / cron / trigger」一类的工具。**以你实际拥有的工具为准，不要凭印象说某个产品有或没有这个功能。**
3. 仓库是否是私有仓库（`gh repo view --json visibility` 或问用户）。中转分支里有视频和文案，建议私有。

## 第 2 步：选频道和时间（问 1 轮）

运行 `python3 $REPO/tools/check_channel.py --all`，列出所有频道和它们现在的 `schedule`。请用户选：

- **启用哪些频道**：写进 `autoreel.config.json` 的 `channels`。
- **每个频道几点发布**：写进 `channel.json` 的 `schedule.publish`。
- **提前多久开始制作**：默认发布前 1 小时，写进 `schedule.make`。CosyVoice 在没有显卡的机器上一期要 15–25 分钟，至少提前 45 分钟。`days_ahead` 为 1 的频道（历史上的今天、成语）每次多做一天，留了余量。

建议：新号每天不超过 5–6 条，同一个整点不要排两条；常见流量时段是 7–9 点、12–13 点、18–22 点。想新建频道就转到 `autoreel-channel` 技能。

## 第 3 步：配音、素材、通知（问 1 轮，可跳过）

- **配音**：默认 CosyVoice3 离线配音（免费，慢）；有火山引擎账号可以用豆包语音（快，按量付费）。见 `docs/部署指南.md` 第 3 步。
- **实拍素材**：Pixabay 的免费 API 密钥（<https://pixabay.com/api/docs/>，登录后页面上直接显示），放在运行环境的环境变量 `PIXABAY_API_KEY` 里。Pexels 已停止发放新密钥，有旧密钥的可以再加 `PEXELS_API_KEY`。
- **通知**：出片成功或失败时推到企业微信、飞书、钉钉、QQ（OneBot）、Bark 等。在 `autoreel.config.json` 的 `notify` 里加一项，写法见 `tools/notify.py` 开头；地址里的密钥写成 `${环境变量名}`，让用户自己在运行环境里设置这个环境变量。**不要让用户把密钥发在对话里。**

## 第 4 步：建定时任务（核心）

每个启用的频道一个任务，在 `schedule.make` 的时间（北京时间）运行。任务指令统一用下面这段，把 `<频道id>` 换掉（`days_ahead` 为 1 的频道把「今天的」改成「今天和明天两期」；读书这类要标记「已做」的频道，加上授权提交那一个文件）：

```
按仓库 AGENTS.md 的说明，制作今天的 <频道id> 频道，用 tools/make.py 推送到 clip-日期-<频道id> 分支（日期按北京时间）。这是我安排的每日任务，我授权你推送这个分支。不要登录或调用任何视频平台。
```

另外建议加一个**发布状态检查**任务（每天在最后一个发布时间后半小时），指令见 `prompts/定时任务.md`。

按第 1 步的判断，三选一：

### A. 你自己能创建定时任务
直接创建：名称写「自影 · <频道名>（HH:MM 制作）」，时间按北京时间（工具要求 UTC 就换算，北京时间 = UTC+8），绑定这个仓库。建完把任务列表（名称、时间、下次运行时间）给用户看。

### B. 用户的工具有定时任务功能，但你不能替他建
给出一张表，让用户逐条在那个工具的界面里粘贴创建：

| 名称 | 每天几点（北京时间） | 仓库 | 指令 |
|---|---|---|---|

并提醒：任务要能访问这个仓库、能联网搜索、能运行 Python / Node / ffmpeg、能 `git push`；第一次运行时如果工具要求确认推送权限，选「允许」。具体菜单位置以那个工具的官方文档为准，不知道就请用户查一下，不要编造。

### C. 工具没有定时任务功能（或用户不想用）
用仓库自带的方案，任选其一：

- **GitHub Actions**（不需要开着电脑）：按 `schedulers/github-actions/README.md` 操作。把模板复制到 `.github/workflows/autoreel.yml`，按用户选的频道和时间改 `cron`（GitHub 的 cron 用 UTC，北京时间减 8 小时；高峰期可能延迟 10–30 分钟，所以提前量要够），在 `AGENT_CMD` 里填用户的 AI 工具命令行，并请用户在仓库 Settings → Secrets 里添加那个工具的 API 密钥。提醒成本：私有仓库每月免费分钟数有限，CosyVoice 很耗时，建议配合火山引擎配音。
- **本机定时**（电脑开着时运行）：按 `schedulers/local/README.md`，用 `schedulers/local/run.sh <频道>` 加 crontab（Linux）或 launchd（macOS）。

## 第 5 步：浏览器插件（用户操作，你来指导）

见 `docs/部署指南.md` 第 5、7 步：GitHub 令牌只给这个仓库 **Contents 读写**；Chrome 加载 `extension/`，填仓库和令牌，扫码登录抖音。插件会自动读到启用的频道和发布时间。

## 第 6 步：试跑一期（推荐）

挑一个频道，按 `autoreel` 技能完整做一期，用 `make.py` 但**不加 `--push`**，把成片发给用户看（能发文件就发，不能就告诉用户 `out.mp4` 的位置）。满意后提交第 2、3 步的配置改动并推送到默认分支，告诉用户从哪天哪个时间开始自动运行。

## 第 7 步：汇报

最后列出：启用的频道和发布时间表、定时任务是怎么建的（A / B / C）、还需要用户做的事（插件、令牌、密钥、在工具里粘贴任务）。
